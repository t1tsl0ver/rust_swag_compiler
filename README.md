# Rust SWAG Compiler

Учебный компилятор Rust-подобного языка. Проект реализуется на C++ и собирается с помощью CMake.

## Быстрый запуск нашего лексера

Лексер уже можно собирать и запускать отдельно от остальных этапов компилятора. Для сборки нужны:

- CMake версии 3.20 или новее;
- компилятор C++ с поддержкой C++17;
- Flex версии 2.6 или новее.

Проверьте, что CMake и Flex доступны из PowerShell:

```powershell
cmake --version
flex --version
```

Из корня репозитория настройте и соберите проект:

```powershell
cmake -S . -B build
cmake --build build --config Debug
```

Запустите лексер, передав ему путь к исходному `.rs`-файлу:

```powershell
.\build\bin\rust_swag_lexer.exe .\_compiler\tests_lexer\positions.rs
```

Лексер печатает каждую найденную лексему в стандартный вывод. Например:

```text
2:5  KW_FOR                           "for"
```

Здесь `2:5` — начало лексемы на второй строке в пятой колонке, `KW_FOR` — её тип, а `"for"` — исходный текст. Поэтому реакция на оператор цикла `for` сейчас видна прямо в консоли. Координаты считаются с единицы; многобайтовый символ UTF-8 занимает одну колонку.

Лексические ошибки выводятся в `stderr`. Коды завершения процесса:

- `0` — файл успешно разбит на лексемы;
- `1` — неверная команда запуска или исходный файл не удалось открыть;
- `2` — обнаружена хотя бы одна лексическая ошибка.

Запустить все автоматические тесты лексера:

```powershell
ctest --test-dir build -C Debug --output-on-failure
```

Исходные правила находятся в `_compiler/lexer/lex.l`. Во время сборки Flex создаёт `build/generated/lex.yy.cpp`; этот сгенерированный файл вручную редактировать не нужно. Входные файлы тестов лежат в `_compiler/tests_lexer/`, а обязательные фрагменты ожидаемого вывода — в `_compiler/tests_lexer/expected/`.

Пока лексер работает как самостоятельная диагностическая программа. Когда появится синтаксический анализатор, реакции правил в `lex.l` будут возвращать типы токенов парсеру, аналогично связке Flex/Bison в справочном компиляторе. Обычные комментарии сейчас тоже показываются как токены, чтобы работу лексера было удобно проверять; парсер сможет их отбрасывать.

Для удобства просмотра имена примитивных типов (`i32`, `bool`, `str` и другие), а также `String` выводятся отдельными диагностическими типами `TYPE_*`. В грамматике самого Rust это идентификаторы, поэтому при подключении парсера их контекстную обработку нужно будет сохранить. Unicode-идентификаторы уже распознаются как UTF-8, но точную проверку свойств Unicode 17 `XID_Start`/`XID_Continue` и NFC-нормализацию предстоит вынести в отдельный этап проверки идентификаторов.

Наш проект и исходный код разрабатываемого компилятора находятся в каталоге `_compiler/`.

Для проверки реализации используется официальный компилятор Rust той же зафиксированной версии: один и тот же `.rs`-файл передаётся оригинальному `rustc` и нашему компилятору, после чего сравниваются результат, сообщения об ошибках и поведение программы.

## Эталонная версия Rust

- Rust: `1.98.1`
- Edition: `2024`
- Commit компилятора: `48a229ceaefd4985c50990b14116b6d856af0985`
- Commit Rust Reference: `86635e30bf861a038dc197d7e16fd09e7e514e7a`

Версию следует указывать явно при каждом запуске, чтобы будущие обновления Rust не изменили результаты тестов.

## Установка оригинального компилятора

Команды ниже предназначены для Windows PowerShell.

1. Установить официальный [rustup](https://www.rust-lang.org/tools/install).
2. Перезапустить терминал, чтобы команда `rustup` появилась в `PATH`.
3. Установить минимальный GNU-toolchain и локальный HTML-мануал:

```powershell
rustup toolchain install 1.98.1-x86_64-pc-windows-gnu --profile minimal --component rust-docs
```

Проверить установленную версию:

```powershell
rustc +1.98.1-x86_64-pc-windows-gnu --version --verbose
```

В выводе должны присутствовать версия `1.98.1` и commit `48a229ceaefd4985c50990b14116b6d856af0985`.

## Проверка `.rs`-теста оригинальным компилятором

Тест может находиться в любом каталоге. Например, чтобы проверить файл `tests\example.rs`:

```powershell
New-Item -ItemType Directory -Force .\build\reference
rustc +1.98.1-x86_64-pc-windows-gnu --edition 2024 .\tests\example.rs -o .\build\reference\example.exe
```

Если компиляция успешна, запустить получившуюся программу:

```powershell
.\build\reference\example.exe
```

Если тест должен содержать ошибку, достаточно передать его `rustc` и изучить диагностику:

```powershell
rustc +1.98.1-x86_64-pc-windows-gnu --edition 2024 .\tests\invalid.rs
$LASTEXITCODE
```

Код завершения `0` означает успешную компиляцию, ненулевой код — отказ компилятора. Эти же тестовые файлы можно передавать нашему лексеру командой из раздела быстрого запуска и сравнивать распознанные лексемы с поведением оригинального компилятора.

## Rust Reference

Открыть установленный локальный HTML-мануал в браузере:

```powershell
rustup doc --toolchain 1.98.1-x86_64-pc-windows-gnu --reference
```

Узнать точный путь к его `index.html`, не открывая браузер:

```powershell
rustup doc --toolchain 1.98.1-x86_64-pc-windows-gnu --reference --path
```
